## Clarified: how castling is (and isn't) represented to learners

Answered a user question on the model-level special-move fix. Precise facts (verified):
- Legality is fully handled (python-chess + masks admit castling/ep/promotion — locked
  by the G3 mask test). The gap is *perception* and *evaluation*, not legality.
- en passant and promotion already have spatial planes (channels 21, 19/20). Castling
  has **none**.
- Castling reaches learners ONLY as the `can_castle` scalar in `board_context_features`
  (channel "can_castle"; 1 if side-to-move has ANY castling rights). Verified that L3
  (perceptron.py:233), L4 (torch_model.py:394), L5 (guided.py:281) and L3.5
  (squarelocal.py:343) all consume `board_context_features`. So castling is NOT
  invisible — but the scalar is global (not per-square), ORs kingside+queenside
  together, and is about *rights* not the *act*.
- `encode_move_feature` has an `is_castling` flag (encode.py:371) and is TESTED
  (test_encode.py:207-223) but has **no production caller** — nothing in the policy
  path uses it. So the move-level castling signal reaches no model. (Tested-but-unused
  helper; not dead code, but no live consumer.)
- value.evaluate() = material + PST only; castling rewarded only incidentally via the
  king PST square. No castling/ep/mobility term.

The fix is two independent levers: (A) castling spatial plane(s) in encode() — a
feature/input change that does NOT touch the eval fn; append-only (new channels at
index 22+, register colour-specific ones in COLOUR_PAIRED_CHANNELS); old checkpoints
still load but need retraining. (B) a castling/king-safety term in value.evaluate() —
the actual eval change; hits L2 first then propagates via search-feedback targets to
L1/L3/L4/L5. Both needed: planes let a learner *see* it, the eval term gives a
*reason*. The G3 census regression is designed to fail (on purpose) the day this lands.

## Decision framing: implications of NOT fixing the special-move gap

User asked "what if I don't fix it?" Answer given (no code change; analysis only):
- For THIS benchmark (purpose = compare naive vs informed learners, not build a strong
  engine), not fixing is defensible, arguably intended. The underplay IS the finding.
- Key structural point: the blind spot is UNIFORM across learners (L1/L3/L4/L3.5 share
  the same encode + eval), so intra-learner comparisons stay valid. The confound is
  localised to the search<->learner boundary: L2 castles because deep minimax sees king
  safety over plies, learners don't. So the search-vs-learner strength gap is INFLATED
  by a fixable special-move artifact, not purely a learning-quality difference. Do not
  overclaim from that gap.
- Costs accepted: strength ceiling on pure learners (plausible mechanism, causality not
  proven from census alone); games look less like real chess; en passant nearly
  invisible (minor). L5/L6 contain search so partially compensate — deficit lands
  hardest on the pure learners.
- Why deferring is low-risk: append-only makes it reversible; the G3 census regression
  keeps the deficit visible so it can't silently distort future results; fix later =
  retrain + re-baseline.
- Revisit if: claiming learners are as strong as possible, wanting the search-vs-learner
  gap to reflect learning quality, or wanting real-looking games.

## External training data for castling — analysis (user question)

User asked "could I just use external training data to make it move that way?"
Verified key fact that REFINES the earlier "needs a castling plane" framing:
- L3's perceptron DOES wire `can_castle` into move scoring: `_context()` returns
  board_context_features (9-dim incl. can_castle) when `use_context=True` (default);
  in `from_logits` it goes `W_ctx @ ctx -> hidden -> W_hid @ hidden` and is ADDED to
  the 64 origin logits (perceptron.py ~261-264). So the castling-relevant features
  (can_castle scalar + king/rook/occupancy planes) are present AND wired into scoring.
- Conclusion: L3's failure to castle is a SIGNAL/REWARD gap, not a feature/capacity
  gap. It can already represent "castle here"; the self-play reward (material+PST
  eval, search feedback) never tells it to. So external supervised data (master-game
  labels) OR an eval term both address the real gap; a dedicated castling *plane* is
  less necessary than the earlier framing implied.

Implications of using external data as the fix:
- Works for L3/L4 (features + pathway exist). Does NOT help L1 (blind, no board
  input) — only a blunt global prior on e1g1/e8g8, castling at wrong times.
- BREAKS the benchmark premise: ladder = "same task, same features, same self-play/
  search signal, vary only the learner." Injecting supervision changes the signal for
  that level; the controlled comparison breaks. Mark that level supervised/off-ladder.
- En passant won't improve (rare in master data too, same as self-play). Promotion
  already fine.
- Adds a dataset dependency (benchmark prizes self-contained, seed-reproducible runs).
- Convergence: the clean way to use external data here is to learn a king-safety/
  castling term and fold it into value.evaluate() / search-feedback targets, not to
  hand-label moves — keeps the self-play structure while fixing the reward.
- BEST immediate use is as a cheap DIAGNOSTIC: briefly train L3 on master-game labels;
  if it learns to castle, gap confirmed as signal (fix reward), not features (no plane
  needed). Answers the open feature-vs-signal question without committing to either fix.

User proposed comparing training paradigms as separate arms: self-play / round-robin /

**Do-ability (verified 2026-10-03):** all four paradigms map to existing hooks —
- self-play: `train_naive.train()` frozen-copy opponent (exists).
- round-robin: `train_naive.train(opponent=...)` override; needs a thin opponent-cycle scheduler.
- graded-by-master: `L3Trainer.train_on_search_feedback` already imitates a stronger player
  (currently depth-5 search = a built-in WEAK master, runnable today); a TRUE master
  (engine / master games) is the only real blocker (not vendored).
- random walks: `RandomPolicy` generates the corpus (the null control).
The genuine gap is a **per-paradigm driver** (train N games with signal S, then bench
vs fixed reference opponents, report rating ± SE) — analogue of bench/ensemble_run.py.
Small build, not a research blocker.

budget; H25 master-graded beats self-taught at equal positions seen (a *decision*
hypothesis that prices the naive premise; doubles as the H23 feature-vs-signal
diagnostic for castling); H26 random-walk control (noise carries no exploitable
