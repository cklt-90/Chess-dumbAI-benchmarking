## Kaggle run 1 failed silently — diagnosis + notebook hardening

- **Symptom:** the kernel reported "done" in ~6 min but did nothing. Log shows
  it died at 19 s: `ls: cannot access 'repo/bench/kaggle'` then
  `can't open file '/kaggle/working/repo/bench/kaggle/kaggle_l3_train.py'`.
- **Root cause:** the clone landed on commit `efcc242` (the OLD `main`, before
  the Kaggle files were pushed). Kaggle `git clone`s `main` at *run time*; the
  run raced ahead of the push that added `bench/kaggle/`. **The clone is not
  pinned, so kernel results are only as new as remote `main` at Run time.**
- **Why it looked green:** papermill recorded the cell error but the notebook
  still finished, so "done" ≠ success. Verify by reading the log / artifacts,
  not the run status.
- **Hardening (committed `3a002ec`, kernel v3):**
  - clone into `/kaggle/temp/repo` (NOT `/kaggle/working/`) so the repo is not
    uploaded as a kernel output artifact;
  - `assert os.path.isfile(SCRIPT)` before running — aborts loudly if
    `bench/kaggle/` is missing;
  - `assert summary.md exists` before reporting.
- **Ordering rule (learned):** Git push to GitHub MUST land *before* the Kaggle
  Run, since the notebook clones at run time. Push → verify remote SHA via the
  GitHub API → then Run.
- **Local-only tooling note:** `git push` hangs in this headless shell (Git
  Credential Manager needs a GUI prompt; `GIT_TERMINAL_PROMPT=0` gives "could
  not read Username"). The user pushes from their own terminal. Kaggle CLI auth
  is machine-wide, so `kaggle kernels push` works here.
- **Kaggle output retrieval:** `kaggle kernels output <owner>/<slug> -p DIR`
  downloads the run's files. The stdout + `out/*.json` are authoritative; the
  Kaggle "working dir" file browser may not show dirs created mid-run.

## Kaggle run 2 SUCCEEDED — measured rate + self-play signal trap

- **Pipeline fully validated on Kaggle** (tiny config, CPU): self-play 5.7 s,
  supervised 443.8 s, eval 20 games; artifacts `l3_both.json` (164 KB, reloads
  as a playable `L3Policy`, plays e2e4 legally), results.json, summary.md.
  Trained L3 lost **0-17-0 to greedy-material** = the **H5 prediction** for a
  barely-trained learner (confirms the harness, not a model bug).
- **MEASURED Kaggle CPU labelling rate: depth-3 = 443.75 s / 300 = 1.48 s/pos.**
  Local was ~0.24 s/pos ⇒ the old "24k positions ≈ 1.6 h" was ~6× optimistic;
  real number is **~10 h**. Revised recommendation: first scale run = **4k
  positions ~1.6 h** (supervised only). This is the key planning number.
- **Self-play signal trap (measured locally, reproducible):**
  - caps `max_plies=120`/`no_progress=60`: **19–20/20 games unfinished** →
    train only via `L3Trainer.white_reward`'s `shaped_reward` branch (final-position
    material, `tanh(eval/1000)*0.3`, mean |reward| ≈ 0.053) — weak.
  - lenient cap (300 plies): games terminate naturally but **40/40 by
    `insufficient_material`**, median 288 plies, **all draws → `white_reward`
    returns exactly (0,0); total reward mass 0.00 over 40 games = ZERO signal.**
  - decisive games across caps 120/200/300/400: **0/20 each**. Blind L3 trades
    down to bare kings.
  ⇒ `selfplay` and `both` arms are **blocked at scale** until the signal is
  fixed. Candidate fixes logged in KAGGLE-PLAN.md: varied `start_fen` (midstate
  store) for diversity; adjudicate truncated games by material as a *decisive*
  shaped terminal (±1) rather than a per-ply nudge; add a temperature floor.
  **Supervised is the only arm worth running at scale now — and it is also the
  H23 headline arm.**
- **Eval caveat:** L3-vs-L3 head-to-head is ~27–29/30 unfinished, so
  `points_pct` is computed over 1–3 decisive games and is statistically
  meaningless. Eval L3 against material (a decisive opponent), not itself.

  Kernel re-pushed as v4 with the updated config comments.
